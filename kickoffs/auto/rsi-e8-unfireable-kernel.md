# E8 the unfireable kernel

## Goal

The sandbox boundary, the tool-grant check, and the refusal path live in the same
editable tree the apply loop can patch. A self-improving system that can edit its
own guardrails does not have guardrails. This is the smallest epic and the one
that bounds what all the others are allowed to touch.

### Mechanisms (exact spec)

Mark a small set of files as outside the self-edit surface:
`mini_ork/runtime/sandbox.py`, the tool-grant check, and the refusal path in
`mini_ork/gates/gate_bootstrap.py`. The apply loop refuses any proposal touching
them, and the scope allowlist of Epic 4 excludes them by construction.

Record every denial in `mini_ork/stores/safety_events.py` with the candidate id
and the offending path, so refusals are visible rather than silent.

`mini_ork/vcs/repo_integrity_guard.py` is the existing guard that takes the check;
extend it rather than adding a new one.

### Tests

Extend `tests/unit/test_repo_integrity_guard.py`. Assert: a candidate patching a
frozen path is refused and a safety event is written; a candidate patching an
allowed path is unaffected.

### Files in scope

- mini_ork/vcs/repo_integrity_guard.py
- mini_ork/stores/safety_events.py
- mini_ork/gates/gate_bootstrap.py (frozen-list registration only)
- tests/unit/test_repo_integrity_guard.py

### Self-application measurement

Inject a candidate that patches each frozen file. Baseline: it lands. After: it is
refused with a safety event. Accepted iff the refusal rate on frozen paths is 100%
and the false-refusal rate on allowed paths is 0%.

Evidence artifact: `${MINI_ORK_RUN_DIR}/kernel-refusal.json` with
`{"frozen_refused": <int>, "frozen_total": <int>, "allowed_refused": <int>, "allowed_total": <int>}`.

### Done When

- The frozen list is enforced at the apply boundary, not by convention.
- Every refusal is recorded and auditable.
- The false-refusal rate on allowed paths is zero.
