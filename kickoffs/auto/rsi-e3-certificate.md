# E3 sequential acceptance certificate

## Goal

`mini_ork/cli/apply.py:evaluate_gate` accepts a candidate on a point estimate
against `MO_APPLY_NONREGRESSION_DELTA`, and
`mini_ork/gates/promotion_gate.py` requires independent support
(`MO_PROMOTION_MIN_RUNS` distinct run ids) but still decides on the estimate. The
tenth marginal directive is judged by the same bar as the first, so a long-running
loop accumulates false promotions by arithmetic alone. Replace the point estimate
with a certificate a self-modifying system can defend.

### Mechanisms (exact spec)

Compute a running lower confidence bound on the reward delta between candidate and
incumbent over the paired probe results, and refuse any directive whose lower
bound is below zero. This replaces the direct comparison at `apply.py:332`.

Keep a per-task-class alpha ledger beside the directive store
(`mini_ork/stores/pattern_store.py`) so the budget is shared across all promotions
for that class: the k-th promotion is tested at a stricter level than the first.
This is the anytime-valid property — the accept rule stays valid no matter how
many times it is applied.

Pre-registration: `apply_run` writes the acceptance predicate — metric, expected
direction, minimum n — to a certificate file BEFORE the candidate is materialized,
and `evaluate_gate` refuses when the predicate file is missing or was modified
after the candidate's `created_at`. This stops the gate from being tuned after
seeing results.

Anchor health in the same certificate: record the `MO_REWARD_ANCHOR` frozen-anchor
pass rate with each promotion, and wire `mini_ork/recovery/circuit_breaker.py`
(`MO_CB_*`) to halt when the anchor degrades while the probe score rises — the
signature of a loop that has begun optimizing its own measurement.

### Tests

Extend `tests/unit/test_apply_gate.py`. Assert: a candidate with a positive point
estimate but a lower confidence bound below zero is REJECTED; the ledger's alpha
tightens across successive promotions of one class; a missing or post-dated
predicate file causes refusal; a synthetic anchor degradation trips the halt.

### Self-application measurement

The decisive test is a null candidate. Baseline: the shipped point-estimate gate
evaluated on a no-op directive, which it sometimes accepts. After: the certificate
gate must reject every no-op. Accepted iff the no-op accept rate is zero AND the
reject rate on a known-good directive is unchanged from baseline.

Instrument: `MO_APPLY_SCORER` over the Epic 2 probe set, with
`MO_APPLY_PROBE_MAX_TASKS` set high enough that n meets `MO_APPLY_MIN_EXAMPLES`.

Evidence artifact: `${MINI_ORK_RUN_DIR}/certificate-null-candidate.json` with
`{"noop_accept_rate": <float>, "known_good_reject_rate": <float>, "n": <int>}`.

### Done When

- Every promotion path refuses on a lower confidence bound below zero, not on a
  point estimate.
- The alpha ledger tightens the bar across promotions of one class.
- Pre-registration is enforced structurally, not by convention.
- The no-op accept rate is zero on the measured probe set.
