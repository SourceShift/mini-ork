# E5 harness-effect isolation

## Goal

mini-ork changes its own recipes and prompts constantly but rarely holds the model
fixed, so an apparent harness win that is really a lane change is promoted as a
harness improvement and the loop learns the wrong lesson with high confidence. A
second, cheaper defect sits beside it: a run that hits its wall-clock ceiling is
scored as a loss even when a passing patch already existed at cancel time.

### Mechanisms (exact spec)

A harness-contrast runner in `mini_ork/learning/benchmark_suite.py` pins the lane
via `MO_FRONTIER_LANE` and runs a pinned probe set under two recipe or harness
versions, writing paired per-task results so `mini_ork/learning/probe_scorer.py`
can attribute the delta to the harness. Wire it next to the `MO_APPLY_*`
non-regression knobs so a win that is really a model change is rejected before
promotion.

Record whether a passing patch existed at cancel time in
`mini_ork/dispatch/telemetry.py`, so a cancelled run is not scored as a loss and
the loop stops learning a false negative.

### Tests

Extend `tests/unit/test_benchmark_suite.py`. Assert: the runner holds the lane
fixed across the two harness versions; a lane swap not declared as a harness
change is attributed to `lane`; a cancelled run with a passing patch is recorded
as such and does not enter the loss column.

### Files in scope

- mini_ork/learning/benchmark_suite.py
- mini_ork/dispatch/telemetry.py
- mini_ork/learning/probe_scorer.py (attribution field only)
- tests/unit/test_benchmark_suite.py

### Self-application measurement

Positive control then negative control. Baseline: run the runner across two
*lanes* with the harness frozen; it must report a non-zero delta and attribute it
to `lane` — proving it can see a real effect. After: run it across two *harness*
versions on one lane; that delta is the harness effect. Accepted iff the positive
control yields `|delta|` above `MO_APPLY_REGRESSION_TOLERANCE` with
`attribution == "lane"`, and the negative control yields `attribution == "harness"`.

Evidence artifact: `${MINI_ORK_RUN_DIR}/harness-contrast.json` carrying both runs'
`{"before": ..., "after": ..., "delta": ..., "attribution": ...}`.

### Done When

- A lane change can never be recorded as a harness change.
- Cancelled-with-passing-patch runs are excluded from the loss column.
- Both controls behave as specified.
