# RSI Tier-1 #9a: strengthen an INADEQUATE suite with tests that kill its surviving mutants (SWE-ABS, shadow)

## Goal

Suite adequacy (`mini_ork/gates/suite_adequacy.py`) is live in the code-fix
test verifier. When the suite cannot kill its own mutants, the green is
downgraded, but nothing tries to make the suite stronger:

- **Strong replay path.** `INADEQUATE` becomes the `adequacy_unverified`
  abstention.
- **Weak path.** Survivors are pasted into a revise round for the same
  implementer that wrote the weak tests.

SWE-ABS (arXiv 2603.00520) strengthens a suite in two steps:

1. it synthesises plausible but incorrect patches;
2. it keeps the generated tests that pass the gold patch and fail those
   patches.

It rejects 19.7% of previously passing SWE-bench patches.

mini-ork has no gold patch, so this minimal version adapts the method:

- **The incorrect patches** are the audit's own surviving AST mutants. They
  are deterministic and can be regenerated by id with
  `suite_adequacy.generate_mutants(..., seed=0)`.
- **The anchor** is the base tree. A generated test is **admitted** only if it
  does all of these:
  - it passes on the candidate;
  - it kills at least one surviving mutant;
  - its base outcome is informative. Failing on the base is new
    fail-to-pass evidence, the same bar the replay uses: kind `target`.
    Passing on the base pins behaviour the patch preserved: kind `preserve`.
- **A test the candidate fails** is recorded as `candidate_red`. This is the
  SWE-ABS rejection signal. It is only recorded: without gold, such a test
  cannot be told apart from a wrong test.

Everything is **shadow**. The verdict is recorded in the verifier payload (key
`suite_strengthening`) and in `<run_dir>/strengthen/`. `pass`, the exit code
and every existing key are unchanged.

**Why the verifier and not a new workflow node.** The code rules a node out:

1. `levels._contract_from_recipe_verifiers` reads every `verifier_<stem>.json`
   at the run root, except the test and behavioral ones, as contract evidence.
   A `strengthen` verifier node would change the `contract` level of every
   code-fix run.
2. A node after `test` runs after the verdict is already written, so a later
   gate could not change `verifier_test.json`.
3. The run-level verdict comes from node status, so a crash in an optional
   node would fail the run.

`_green_pass` already holds the audit result, the base-ref helpers and the
revise bookkeeping.

**Prerequisite.** This kickoff builds on `rsi-t1-certify-codefix`, merged
first. It reuses `LocalTreeRunner` and `bounded_dispatch` from
`mini_ork/certify/codefix_terms.py`, and the `_git_toplevel` helper and the
`CERTIFY` payload slot from `recipes/code-fix/verifiers/test.py`.

All paths are relative to the repository root.

## Mechanism (exact spec)

### 1. `mini_ork/gates/suite_strengthen.py` (new)

Allowed imports:

- stdlib;
- `from mini_ork.gates import suite_adequacy`;
- `from mini_ork.certify import codefix_terms`;
- `from mini_ork.certify.context import module_name, imports_code_under_test`.

The module never raises out of `strengthen`.

- **`MODE_ENV = "MO_SUITE_STRENGTHEN"`.**
- **`mode(environ=None) -> str`.** The same parse as `codefix_terms.mode`:
  - `0`, `off`, `false`, `no` → `"off"`;
  - `1`, `gate` → `"gate"`;
  - anything else, including unset → `"shadow"`.

  `gate` is reserved: in this kickoff it behaves exactly like shadow, apart
  from the recorded `mode`.
- **`settings(environ=None) -> dict`.** Returns
  `{"max_survivors": int, "max_tests": int, "timeout_s": float}`, from:
  - `MO_SUITE_STRENGTHEN_MAX_SURVIVORS` (default 5, clamped 1..20);
  - `MO_SUITE_STRENGTHEN_MAX_TESTS` (default 3, clamped 1..10);
  - `MO_SUITE_STRENGTHEN_TIMEOUT_S` (default 60.0, at least 1.0).

  An unparsable value gives the default.
- **`descriptor(m) -> str`.** Returns
  `f"{m.id} {m.file}:{m.line} {m.operator}: {m.original} -> {m.mutated}"`.
- **`match_survivors(repo_dir: str, report: dict) -> tuple[list, list[str]]`.**
  - Regenerate the mutants with
    `suite_adequacy.generate_mutants(repo_dir, report["files"], max_mutants=report["max_mutants"], seed=0)`.
  - For each survivor dict in `report["survivors"]`, in order, find the
    `Mutant` with the same `id` whose `(file, line, operator, original, mutated)`
    are all equal to the survivor's. Matched Mutants go to the first list;
    survivor ids with no match go to the second.
  - On any exception, return `([], [all survivor ids])`.
- **`admissible(src: str, modules: tuple[str, ...]) -> tuple[bool, str]`.**
  Checks, in order:
  - the source parses, else `(False, "does not parse")`;
  - it has at least one top-level `def test_*`, else
    `(False, "no top-level test function")`;
  - `imports_code_under_test(src, modules)` holds, else
    `(False, "does not import the code under test")`.

  Otherwise it returns `(True, "")`.
- **`build_prompt(issue: str, survivors: list, candidate_dir: str, max_tests: int) -> str`.**
  The prompt contains:
  - the literal marker `STRENGTHEN THE SUITE`;
  - `issue[:1800]`;
  - one `descriptor(m)` per line;
  - the candidate source of each distinct survivor file, under a
    `# file: <path>` header, at most 6000 chars in total.

  It asks for at most `max_tests` fenced python blocks. Each block must be a
  self-contained pytest module that imports the code under test and asserts
  the behaviour the **issue** intends at the mutated lines.
- **`strengthen(report: dict, *, issue: str, candidate_dir: str, base_dir: str, mode: str = "shadow", dispatch=None, python: str | None = None, timeout_s: float | None = None, max_survivors: int | None = None, max_tests: int | None = None, out_dir: str | None = None) -> dict`.**

  **Return shape.** Always exactly these 12 keys: `mode`, `status`, `reason`,
  `targeted`, `unmatched`, `tests`, `admitted`, `newly_killed`,
  `score_before`, `score_after`, `verdict_after`, `would_rescue`. `status` is
  one of `"ran"`, `"skipped"`, `"error"`, and `score_before = report.get("score")`.
  Skipped and error records have:
  - `targeted`, `tests`, `admitted`, `newly_killed` all `[]`;
  - `unmatched` as computed, else `[]`;
  - `score_after=None`, `verdict_after=None`, `would_rescue=False`.

  **Skips, in order:**
  1. `report.get("verdict") != "INADEQUATE"`, or no survivors →
     `"not inadequate"`.
  2. `not issue.strip()` → `"no kickoff text"`.
  3. `report["files"]` is not a list, or `report["max_mutants"]` is not an int
     → `"report lacks files/max_mutants"`.
  4. No survivor matched → `"no survivor could be regenerated"`.

  No dispatch happens on any skip. `None` arguments resolve from `settings()`.

  **The run:**
  1. `targeted` is the ids of the first `max_survivors` matched mutants.
  2. Set `modules` to the non-None `module_name(m.file)` values of the
     targeted mutants.
  3. Set
     `raw = (dispatch or codefix_terms.bounded_dispatch())(build_prompt(issue, targeted_mutants, candidate_dir, max_tests))`.
  4. Take the python blocks with
     ``re.compile(r"```(?:python)?\s*\n(.*?)```", re.S)``, keep the first
     `max_tests`, and name them `t1`, `t2`, … in order.
  5. Build `runner = codefix_terms.LocalTreeRunner(base_dir, candidate_dir, python=python, timeout_s=timeout_s)`.
  6. Make one mutant copy:
     `shutil.copytree(candidate_dir, <mkdtemp(prefix="mo-strengthen-")>/repo, symlinks=True, ignore=shutil.ignore_patterns(".git", "__pycache__", ".pytest_cache", ".mypy_cache", ".ruff_cache", ".tox", ".venv", "venv", "node_modules", ".mini-ork"))`.
     For each targeted mutant:
     - write `m.source` to `<copy>/<m.file>`;
     - run every candidate-passing test with `runner.run_in(copy, src)`;
     - restore the original candidate file bytes.

     `rmtree` the copy in `finally`. Never write inside `candidate_dir` or
     `base_dir`.

  **Each test record** has exactly the keys `name`, `admissible`, `why`,
  `on_candidate`, `on_base`, `kills` and `kind`. It is classified in this
  order:
  - Not admissible → kind `"inadmissible"`. No runs; `on_candidate` and
    `on_base` are `None`; `kills` is `[]`.
  - `on_candidate = runner.run_in(candidate_dir, src).status`. When it is not
    `"passed"` or `"failed"`, the kind is `"abstained"` and the base is not
    run.
  - `on_base = runner.run_in(base_dir, src).status`.
  - When `on_candidate == "failed"`, the kind is `"candidate_red"` and `kills`
    is `[]`.
  - Otherwise, `kills` is the targeted ids, in targeted order, whose mutant
    run has status `"failed"`. The kind is:
    - `"no_kill"` when `kills` is empty;
    - else `"target"` when `on_base == "failed"`;
    - else `"preserve"` when `on_base == "passed"`;
    - else `"unanchored"`.

  **The result:**
  - `admitted`: the names of kind `target` or `preserve`.
  - `newly_killed`: the targeted ids, in targeted order, that some admitted
    test kills.
  - `score_after = round((killed + len(newly_killed)) / (killed + survived), 3)`,
    with `killed = int(report.get("killed", 0))` and
    `survived = int(report.get("survived", 0))`. It is `None` when the
    denominator is 0.
  - `verdict_after`: `"ADEQUATE"` when `score_after` is not None and
    `score_after >= float(report.get("min_score", 0.6))`, else
    `"INADEQUATE"`.
  - `would_rescue = verdict_after == "ADEQUATE" and bool(admitted)`.
  - `status` is `"ran"`. `reason` is `"no test generated"` when there are no
    blocks; otherwise it is
    `f"{len(admitted)} of {len(tests)} generated tests admitted; {len(newly_killed)} of {len(targeted)} targeted survivors killed"`.

  **Files.** When `out_dir` is set, write:
  - every block to `<out_dir>/<name>.py`;
  - the returned dict to `<out_dir>/strengthen.json` (`indent=2`).

  Swallow `OSError`.

  **Errors.** An unexpected exception gives `status "error"` with reason
  `f"{type(e).__name__}: {e}"`.
