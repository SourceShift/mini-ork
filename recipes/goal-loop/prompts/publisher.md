# Publisher — goal-loop

You receive the verifier's wave report + the goal-state map + the sweep plan.
Produce ONE human-readable markdown report so the operator can decide whether
to ship, run another wave, or stop.

## What you read
- `${MINI_ORK_RUN_DIR}/panel-verdict.json` — `{"verdict": "pass"|"fail", "failing_units": [...], "total_units": N}`
- `${MINI_ORK_RUN_DIR}/goal-state.json` — per-unit `{"pass": bool, "reason": str}`
- `${MINI_ORK_RUN_DIR}/sweep-plan.json` — list of `{unit_id, child_recipe, kickoff_hint}` selected for this wave
- `${MINI_ORK_RUN_DIR}/plan.json` — wave objective + goal config

## What you produce

Write `${MINI_ORK_RUN_DIR}/goal-loop-wave-report.md`:

```markdown
# Goal-loop wave — <objective>

**Verdict**: <pass|fail> · **Total units**: <N> · **Failing**: <M> · **Planned fixes**: <K>

> <one-sentence next-action: ship if pass, re-run wave if fail, stop if iteration budget exhausted>

## Failing units
| Unit | Reason | Child recipe |
|---|---|---|
| <unit_id> | <reason from goal-state.json> | <child_recipe> |
| …

## Wave config
- target cwd: <goal_target_cwd>
- units cmd: `<goal_units_cmd>`
- predicate cmd: `<goal_predicate_cmd>`
- max children per wave: <goal_max_children_per_wave>

---
Generated by goal-loop · run_id <MINI_ORK_RUN_ID>
```

Keep it scannable — operator reads top-to-bottom in < 60s and knows whether to
ship, re-run, or stop. Write the file. Nothing else.
