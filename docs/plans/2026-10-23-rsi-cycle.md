# RSI cycle — find, suggest, implement, validate, learn, repeat (mini-ork on itself)

*2026-10-23 · status: phase 0 run complete (1 merged fix, 5-item backlog) · phase 1 built and landed its first merged cycle (2026-10-26)*

## Goal

A loop that improves the mini-ork framework without a person in the middle: it
finds the weakest point from real evidence, proposes one change, implements it in
an isolated worktree, validates it with checks the implementer cannot influence,
merges or rejects it, records why, and starts over. Every stage reuses an RSI
technique that already ships in mini-ork; the cycle is the composition, not new
machinery.

## The graph

```
            ┌───────────────────────── next cycle ─────────────────────────┐
            ▼                                                               │
 HARVEST ─► FIND ─► SUGGEST ─► IMPLEMENT ─► VALIDATE ─► DECIDE ─► LEARN ───┘
 (no LLM)  (4-family  (rank +    (framework-  (independent  (merge /   (ledger, credit,
            lens       filters +  edit child   of the        quarantine  collapse halt,
            panel)     kickoff)   run)         implementer)  / reject)   lessons)
```

| Stage | What it does | Shipped pieces it uses |
|---|---|---|
| HARVEST | Deterministic signal pull, no model: engine-layer failures (`recovery/diagnose.py`), supervisor actions, recurring code findings and whether they landed (`learning/code_findings.py`), revise-round value (`learning/revise_value.py`), screened lanes (`dispatch/screening.py`), cost hot spots (`llm_calls`), environment-dependent tests, unbuilt techniques from the latest `rsi-technique-review` report | diagnosis ledger, R10 recurrence, CoBa history, RouteMoA screen, cost ledger |
| FIND | Four lenses on four model families, anonymized before synthesis (the `refactor-audit` panel shape); each proposes at most 3 candidates, each citing evidence a query or a `file:line` can re-check | panel heterogeneity gate (`gates/panel_heterogeneity.py`) |
| SUGGEST | Rank on a family different from the implementer's; deterministic filters drop a candidate that (a) matches a signature that already failed (outcome-tagged edit memory), (b) touches a frozen path (`config/kernel-frozen.yaml`), (c) spans more than 5 files, or (d) names no measurable success metric and command. The winner becomes a framework-edit kickoff from a template that lists full paths, schema enum values and the pinning tests in scope; `kickoff_lint` must pass | frozen kernel (SDE-2), kickoff lint, the kickoff lessons from the 10-22 program |
| IMPLEMENT | One `framework-edit` child run in a fresh worktree off `origin/main`: blind spec tests, kickoff-contract verifier, static checks, reviewer; graph patches and the supervisor handle repair | framework-edit, graph patches (SDE-5/6), CoBa revise stop |
| VALIDATE | Checks the implementer cannot see or edit: the importer gate (tests that import a changed module, one transitive level), the frozen framework-edit probe set through `probe_scorer` with the blind-rerun control arm, a critic panel whose families differ from the implementer's (gate exogeneity), suite adequacy (mutation kill rate), and the kickoff's own before/after metric | importer gate, probe set (`7be81f11`), control arm (G06-T03), suite adequacy |
| DECIDE | All gates green → `make worktree-merge` with a recorded revert commit; any gate red but the change plausible → quarantine the branch with the failing gate named; otherwise reject | worktree-merge discipline, EvoUndo revert path |
| LEARN | Append the cycle to a ledger (signature, kind, gates, metric delta, merged sha); credit each candidate source (lens, technique, harvest signal) by its merge rate with SimUtil-UCB so FIND weights better sources next time; run the collapse check (score vs anchor divergence) and halt the loop through the circuit breaker if it trips; author lessons through the Trace2Skill conflict check | collapse halt (G01-T04), SimUtil-UCB (`learning/item_utility.py`), Trace2Skill (`learning/lesson_conflict.py`) |
| LOOP | `mini-ork rsi-cycle [--once] [--hours H] [--budget USD]` under a lease; per-cycle and daily budget; stops on collapse or when CoBa says another cycle is not worth its cost; optional launchd cadence like the supervisor | lease store, cost circuit, CoBa |

Backlog the loop found in itself (cycle 3 synthesis, kept at
`mini-ork-worktrees/_rsi/cycle3-synthesis.md`):

1. The post-run learning pass fails 13 of 13 calls: the detached reflect child
   inherits a cwd the runner deletes, and reflect resolves its lane from the raw
   template rather than the effective lane policy — so `gradient_records` stays 0 and
   the loop never learns between iterations.
2. The deterministic gates are near-vacuous on Python changes: `no-regression` checks
   only shell files and passes on zero benchmark rows; `bash -n` runs on the Python
   `bin/mini-ork`; `self-tests-pass` has no timeout.
3. The kickoff scope parser turns "Leave `.mini-ork/` untouched" into an allow-list
   entry and parses the branch name as a path.
4. `learning_record` never marks an implemented finding resolved, so dedupe and
   convergence detection cannot work.
5. The runner never passes `--deadline` to the inner run, so node timeouts ignore the
   iteration's remaining time and an overrun throws away all spend (cycle 3's loss).

Fix #5 first (it caps the loss of every later cycle), then #1 (no learning without it).

Operational hazard seen: the recipe's publisher commits `docs/improvements/self-improve-latest.md`
straight into the primary checkout's local `main`; it was reconciled through a gated
worktree merge. Phase 1's DECIDE stage must commit only inside the cycle's worktree.

What phase 0 lacks (the phase-1 work): the implementer is one bare node rather than
a framework-edit child (no blind spec tests, no kickoff contract), there is no
failed-signature memory, no probe or control-arm validation, no collapse halt, and
the frozen kernel is not enforced.

## Phase 1 status (2026-10-26)

The loop is built and has closed one gap end to end. C1–C4 live in `mini_ork/rsi/`
(harvest → queue → suggest → implement → validate → decide → learn), `recipes/rsi-cycle/`,
`recipes/rsi-critic/`, `mini_ork/cli/rsi_cycle.py` and `db/migrations/0084_rsi_cycles.sql`;
C5's launchd example and the two-tier config key are in place and the service cadence is
still operator-run rather than scheduled.

First merged cycle `rsi-c1793010091-2818cd9c` (2026-10-26), candidate
`rsi-48a7170cecd158d7` — `verifier_results.confidence` never recorded:

- all eleven gates green (G1–G11), two exogenous critics unanimous (families `zai` and
  `minimax`), cost **$1.00** — cheaper than every earlier cycle ($1.29–$1.69);
- `merged_sha 398889bc`; the patch makes `_record_verifier_result` pass a *measured*
  confidence (rubric-item agreement) instead of a constant, and stays NULL when no
  rubric exists;
- the next `plan` no longer carries the gap: `rsi_candidates` has it `merged` with its
  sha, and the previously-targeted variant is `fixed_externally` ("not reproduced by
  harvest") — the reconciliation that stops the queue re-targeting a closed gap.

Seven loop defects these cycles exposed. The first three were found by the merged cycle
and fixed in `mini_ork/rsi/`:

- **`critic_json` was never written** (`14c6253e`), so a split's reasoning existed only
  in the run dir. Cycle 15 was quarantined on `critic_split` with no operator-visible
  explanation; the merged cycle now stores both verdicts with family and `why`.
- **V1's `fix_hint` named only the reader** (`4868cac7`), and the cycle-15 child duly
  produced a test-only fix that would have changed nothing in production. Sharpen the
  hint and the next child fixes the producer — evidence that the hint, not the child, is
  the lever when a critic rejects on root cause.
- `rejected` cycles stored no reason (`8b4c39c7`): the code now lands in `halt_reason`,
  so `rsi-cycle list` can tell a claim conflict from a bad proposal after a cron run.

Cycles 17 and 18 then died inside SUGGEST — different causes, both in the run's own
guard rails rather than in the proposal:

- **Cycle 17 (`rsi-c1793018612-81a05701`): the wall was spent before the synthesizer.**
  Three lenses dispatch in parallel, the synthesizer runs after them, and the only
  per-node bound was the runtime default `MO_NODE_TIMEOUT_S=1500` — 83% of the 1800 s
  wall. One lens held a single call for 1111 s, the run was killed at its wall (rc 124)
  and never wrote `proposal.json`. It spent $0.42 and recorded **$0.00**, because the
  `except BaseException` path finished the row without a cost. Both fixed in
  `24488aee`: SUGGEST caps each node at half its wall (lowering, never raising, an
  inherited value — the critic run is deliberately *not* capped, since its two nodes are
  the whole run), and an errored cycle sums its own `llm_calls` rows by run-id prefix.
- **Cycle 18 (`rsi-c1793021670-6832e26f`): a healthy plan failed `step-rules-gate`.**
  The SUGGEST run reached the synthesizer and wrote `proposal.json` (so the wall fix
  held), then the recipe run's contract verify failed on the globally registered
  `step-rules` gate. `named_test_path_exists` scans each verifier command for
  path-shaped tokens; three of the plan's six checks were `python3 -c "…"` programs, and
  it read their *source* as shell arguments — `R + '/proposal.json'` became the absolute
  path `/proposal.json`, the assertion `'routing.py' in summary` became a missing file.
  Five phantom paths, every real named path present. Fixed in `c79d189a`: the command is
  split with `shlex` and the operand of an interpreter's code flag is dropped before the
  token scan; a path passed *after* the program, and `tar -c file`, are still checked.
  The cycle still recorded its $1.52 spend — the cycle-17 fix earning its keep on the
  very next failure.

Cycles 19 and 20 then exposed one defect wearing two shapes: **each stage writes its own
verdict file and the driver reported the exit code instead.**

- **Cycle 19 (`rsi-c1793025182-40a64df3`): the profile asked a dead lane for permission.**
  The SUGGEST kickoff declared no verification command, so `profile_gate` asked three
  questions and dispatched `profile_answerer` to answer them — on `minimax`, whose fuse
  was open on quota. The plan stopped at `plan_status=needs_answers` before any node ran
  and the cycle said only `exited 6 without a proposal.json`, 30 s and $0.00 later. Fixed
  in `25e3dbee`: both recipe kickoffs now carry `## Verification commands`, which readies
  the profile at confidence 0.9 with the questions *deferred rather than dropped* and no
  model call at all; and a run that stops this way reports `never dispatched the planner:
  plan_status=needs_answers, blocked_by run_profile (questions: 3)`.
- **Cycle 20 (`rsi-c1793026100-004e380c`): correct refusal, useless message.** Lane
  preflight did its job — it refused the run before any dispatch because `minimax` was
  out of quota, which also meant the promise of a cheap failure was kept ($0.057). But
  the cycle reported `exited 75 without a proposal.json`, while
  `<run_dir>/lane-preflight.json` named the lane, the node (`lens_oracle`) and the
  provider's words (`HTTP 429 … Token Plan usage limit reached`). Fixed in `7cc0ea82`:
  the reason is read from the verdict file and truncated at 200 characters before it
  reaches `halt_reason`.

With cycle 20 the loop is honest but **lane-blocked**, not code-blocked: this host's
`.mini-ork/config/agents.local.yaml` overlay serves the `*_lens` panel, `implementer`,
`researcher` and `publisher` roles from `minimax`, and the minimax Token Plan is
exhausted. `quota` is a *terminal* fuse category with one strike, so a single 429 holds
the lane shut for `MO_FUSE_WINDOW_HOURS` (6 h). The SUGGEST lens panel needs three
distinct families and this host serves three (`zai`, `deepseek`, `minimax`) — so until
that lane is live or the panel is repointed, every cycle stops at SUGGEST by design,
after naming the lane. Nothing about that is a defect in the loop.

The lesson repeated across all of them: when a cycle fails, the driver, the recipe and
the gates are suspects before the model is. None of these five cycles produced a bad
proposal; every one was stopped by a guard, a timeout or a lane that was wrong about the
run — or by the driver refusing to say what the run had already written down.

## Two tiers

- Simple: `mini-ork rsi-cycle --once` on a laptop, local SQLite ledger, local worktrees.
- Secure: the driver as a service against the shared DB, framework-edit children on
  sandboxed nodes with scoped credentials, merges through the oversight inbox's
  notification (never an approval gate — the TRUE-RSI rule stands).
