# RSI cycle — find, suggest, implement, validate, learn, repeat (mini-ork on itself)

*2026-10-23 · status: phase 0 running (one-hour self-improve loop) · design for phase 1*

## Goal

A loop that improves the mini-ork framework without a person in the middle: it
finds the weakest point from real evidence, proposes one change, implements it in
an isolated worktree, validates it with checks the implementer cannot influence,
merges or rejects it, records why, and starts over. Every stage reuses an RSI
technique that already ships in mini-ork; the cycle is the composition, not new
machinery.

## The graph

```
            ┌───────────────────────── next cycle ─────────────────────────┐
            ▼                                                               │
 HARVEST ─► FIND ─► SUGGEST ─► IMPLEMENT ─► VALIDATE ─► DECIDE ─► LEARN ───┘
 (no LLM)  (4-family  (rank +    (framework-  (independent  (merge /   (ledger, credit,
            lens       filters +  edit child   of the        quarantine  collapse halt,
            panel)     kickoff)   run)         implementer)  / reject)   lessons)
```

| Stage | What it does | Shipped pieces it uses |
|---|---|---|
| HARVEST | Deterministic signal pull, no model: engine-layer failures (`recovery/diagnose.py`), supervisor actions, recurring code findings and whether they landed (`learning/code_findings.py`), revise-round value (`learning/revise_value.py`), screened lanes (`dispatch/screening.py`), cost hot spots (`llm_calls`), environment-dependent tests, unbuilt techniques from the latest `rsi-technique-review` report | diagnosis ledger, R10 recurrence, CoBa history, RouteMoA screen, cost ledger |
| FIND | Four lenses on four model families, anonymized before synthesis (the `refactor-audit` panel shape); each proposes at most 3 candidates, each citing evidence a query or a `file:line` can re-check | panel heterogeneity gate (`gates/panel_heterogeneity.py`) |
| SUGGEST | Rank on a family different from the implementer's; deterministic filters drop a candidate that (a) matches a signature that already failed (outcome-tagged edit memory), (b) touches a frozen path (`config/kernel-frozen.yaml`), (c) spans more than 5 files, or (d) names no measurable success metric and command. The winner becomes a framework-edit kickoff from a template that lists full paths, schema enum values and the pinning tests in scope; `kickoff_lint` must pass | frozen kernel (SDE-2), kickoff lint, the kickoff lessons from the 10-22 program |
| IMPLEMENT | One `framework-edit` child run in a fresh worktree off `origin/main`: blind spec tests, kickoff-contract verifier, static checks, reviewer; graph patches and the supervisor handle repair | framework-edit, graph patches (SDE-5/6), CoBa revise stop |
| VALIDATE | Checks the implementer cannot see or edit: the importer gate (tests that import a changed module, one transitive level), the frozen framework-edit probe set through `probe_scorer` with the blind-rerun control arm, a critic panel whose families differ from the implementer's (gate exogeneity), suite adequacy (mutation kill rate), and the kickoff's own before/after metric | importer gate, probe set (`7be81f11`), control arm (G06-T03), suite adequacy |
| DECIDE | All gates green → `make worktree-merge` with a recorded revert commit; any gate red but the change plausible → quarantine the branch with the failing gate named; otherwise reject | worktree-merge discipline, EvoUndo revert path |
| LEARN | Append the cycle to a ledger (signature, kind, gates, metric delta, merged sha); credit each candidate source (lens, technique, harvest signal) by its merge rate with SimUtil-UCB so FIND weights better sources next time; run the collapse check (score vs anchor divergence) and halt the loop through the circuit breaker if it trips; author lessons through the Trace2Skill conflict check | collapse halt (G01-T04), SimUtil-UCB (`learning/item_utility.py`), Trace2Skill (`learning/lesson_conflict.py`) |
| LOOP | `mini-ork rsi-cycle [--once] [--hours H] [--budget USD]` under a lease; per-cycle and daily budget; stops on collapse or when CoBa says another cycle is not worth its cost; optional launchd cadence like the supervisor | lease store, cost circuit, CoBa |

## Phase 0 (running now): the existing self-improve loop, repaired for today

`mini-ork self-improve --soft-cap-hours 1 --hard-cap-hours 1.25` against a dedicated
home (`/Volumes/docker-ssd/ps/mini-ork-rsi-home/.mini-ork`) — the runner overwrites its
home's `agents.yaml`, so it must not run on the primary home. What had to change:

- lanes: the recipe names codex and kimi, both dead; a home overlay maps
  `codex_lens → deepseek_flash`, `kimi_lens → glm` (4 families: Anthropic, MiniMax,
  Zhipu, DeepSeek);
- the `self-tests-pass` gate ran the whole suite (~60 min here, one iteration would
  eat the hour); `MINI_ORK_SELF_IMPROVE_TEST_CMD` now runs a scoped importer gate
  (`mini-ork-worktrees/_rsi/importer_gate.py`) that deselects the three known
  environment-dependent failures;
- `MO_RUNTIME_BACKEND=local` (the runner defaults to `bubblewrap`, Linux-only);
- no auto-merge: successful iterations stay on `self-improve/iter-*` branches and are
  reviewed clause by clause before merge.

What phase 0 lacks (the phase-1 work): the implementer is one bare node rather than
a framework-edit child (no blind spec tests, no kickoff contract), there is no
failed-signature memory, no probe or control-arm validation, no collapse halt, and
the frozen kernel is not enforced.

## Two tiers

- Simple: `mini-ork rsi-cycle --once` on a laptop, local SQLite ledger, local worktrees.
- Secure: the driver as a service against the shared DB, framework-edit children on
  sandboxed nodes with scoped credentials, merges through the oversight inbox's
  notification (never an approval gate — the TRUE-RSI rule stands).
